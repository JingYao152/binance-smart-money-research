The implementation uses documented Kopyon v5 trader routes and Binance public market-data routes. This audit records field availability only. It contains no trader identity, response values, downloaded records or performance results.

The initial implementation's private live probe verified reachable Kopyon profile, open-position, position-history and order-history schemas. The project design records that evidence; no new live trader API call was made for this release task. Field availability describes the probe, not a guarantee that every trader or future response supplies every field. Current public documentation was checked again on 2026-10-25 through the [Smart Money reference](https://kopyon.com/binance-smart-money-api/) and [shared API documentation](https://kopyon.com/docs/).

The permitted route family is `https://api.kopyon.com/v5/binance-smart-money`. The collector uses `traderSearch`, `traderProfile`, `traderChart`, `openPositions`, `positionHistory` and `orderHistory`. Search resolves provider trader IDs; history follows cursors. Sharing flags and hidden responses can limit coverage, and an all-history request means every record the provider returns rather than a complete account lifetime.

Verified profile field groups include performance metrics and sharing flags. Open-position field groups include symbol, direction, size, entry and mark prices, leverage, margin, unrealized PnL and source margin information. Position-history field groups include position identifiers, status, side, leverage, entry and close prices, open and close times, opened/closed volume, gross PnL, funding PnL, trading fees, liquidation fees and net PnL where components are known. Order-history groups include symbol, order side, position side, price, quantity, quote quantity and timestamps.

Stable per-order IDs, per-order commission, per-order realized PnL, historical margin and individual account funding charges remain unconfirmed. A content fingerprint is a local deduplication key when an identifier is absent, not proof of a distinct exchange order. Sampled PnL or ROI charts do not provide a complete account-equity ledger. Unknown fields and costs stay missing; reconciliation requires every relevant component.

The Binance collector uses only `GET /fapi/v1/klines` and `GET /fapi/v1/fundingRate` from `https://fapi.binance.com`, documented in the [official USDⓈ-M market reference](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data). Kline schema includes open/close times, OHLC, base and quote volume, trade count and taker-buy volume. Funding history includes symbol, funding time, signed rate, mark price and rate type when returned. These are documented market fields; this task did not perform a fresh live market-data probe. COIN-M trader history can be retained, while matching COIN-M market collection is not implemented.

Raw retrievals keep source, route, query parameters, retrieval timestamp, HTTP status, payload and content hash. Each normalized record points to its retrieval when available. Analysis features use only bars closed strictly before a trade event. Funding simulation uses the relevant symbol and position interval, and reports unsupported/missing cost information. Evidence bundles distinguish observed provider fields, derived summaries and proposed hypotheses.

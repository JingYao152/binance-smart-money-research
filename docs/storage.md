The local evidence store requires the declared DuckDB dependency. From the project root, install with `python -m pip install -e '.[test]'` and run the focused suite with `python -m pytest tests/test_storage.py tests/test_normalize.py tests/test_quality.py -q`. Tests create temporary databases and never call the network.

`ResearchStore(path).initialize()` creates schema version 1. Use the store as a context manager or call `close()`. `rows(table)` returns dictionaries for an allowlisted table. `upsert_history(table, records)` accepts allowlisted columns, binds values as parameters and commits each batch atomically. Keys are trader, market and record ID for positions and orders; symbol, interval and open time for K-lines; symbol and funding time for funding rates.

`save_raw(source, endpoint, params, payload, status, fetched_at)` appends a response and returns its UUID. JSON arrays, objects and scalar values are accepted. The SHA-256 content hash covers the payload encoded as UTF-8 JSON with sorted object keys, compact separators and unchanged array order. Identical payloads fetched twice retain separate UUIDs and retrieval times. Query parameters, response status and endpoint remain alongside each payload. Raw responses have no upsert method.

`normalize_position(trader_id, market_type, record, raw_response_id=..., fetched_at=...)` maps source `openedAt` and `closedAt` to `open_time` and `close_time`. `updatedAt` becomes `updated_at`, and `marginMode` becomes `margin_mode`. `normalize_order` maps `createdAt` to `created_at` and the common event field `timestamp`, and maps `updatedAt` to `updated_at`. Every row retains the complete source object in `raw_fields`, the `sourceDetails` value in `source_details`, and source, trader, market and retrieval provenance. Unknown fields stay in the source JSON. Missing fields remain SQL NULL.

Position identity uses `positionId` when present. Otherwise, positions and all orders receive SHA-256 of canonical JSON containing trader ID, market type, resource and the full source record. Retrieval metadata is excluded. This fingerprint cannot distinguish distinct orders with identical source content. A change to source content creates a new fingerprint. `fingerprint_counts` in the integrity report exposes the affected scope; these are possible identity ambiguities rather than proof of an actual cryptographic collision.

`save_profile(trader_id, profile, raw_response_id=..., fetched_at=...)` appends a profile snapshot. `save_chart_points(trader_id, period, chart_type, points, raw_response_id=..., fetched_at=...)` appends chart point snapshots. Attach each raw response before normalizing its data. `replace_open_positions(trader_id, market_type, records)` validates scope, upserts its batch and removes stale rows for that scope. Only replace a snapshot after fetching its complete visible set.

`save_checkpoint(trader_id, market_type, resource, watermark=..., cursor=..., status=..., error=..., updated_at=...)` persists one current checkpoint. `get_checkpoint` returns it or None. Callers own checkpoint progression and must retain the previous watermark after an incomplete run. The later ingestion layer handles pagination and completion.

`check_integrity(store, trader_id)` returns read-only counts, missing critical fields, hidden sharing flags, duplicate key counts, fingerprint counts, cursor and sync errors, timestamp errors, and PnL residuals. Cursor streams are separated by route, market and request window; a request without a cursor starts a new stream. A database with no observations is labeled uncollected. A successful empty response is observed and has zero records. Observed means local evidence exists; it does not guarantee complete provider history. Duplicate counts describe current normalized keys, which database constraints protect, rather than unavailable provider trade counts.

PnL residual is source net PnL minus gross PnL minus signed funding PnL plus trading fee plus liquidation fee. All five components must exist; otherwise reconciliation is counted as unverifiable. Source fees are expected to use the documented positive expense convention. A residual above 1e-8 is reported and source values remain unchanged. Raw JSON retains exact source decimal strings; normalized numeric columns use DOUBLE for local analysis.
